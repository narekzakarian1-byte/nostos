# NOSTOS — ТЗ на прототип

Документ для исполнения через Claude Code. Читается вместе с `GDD.md`, `BALANCE.md`, `balance.json`.

---

## 0. Что именно проверяет прототип

Один вопрос: **приятно ли подходить к врагу, смотреть на три иконки и решать «дожать или отойти» — десять минут подряд, на белых квадратах, без графики и без сеттинга.**

Если ответ «нет» — Одиссей, чернофигурная керамика и тринадцать островов не спасут, и лучше узнать это на третий день, чем на шестой месяц.

Всё остальное в этом документе подчинено этому вопросу.

## 1. Стек

**Прототип: TypeScript + HTML5 Canvas + Vite. Без игрового движка.**

Почему не Unity и не Godot на этом этапе:
- проверка на телефоне за 5 секунд через локальный адрес в браузере, а не через сборку APK
- Claude Code пишет чистый TypeScript быстрее и надёжнее, чем C# внутри чужого редактора
- вся логика в текстовых файлах, которые полностью помещаются в контекст
- нет бинарных ассетов, которые ломают diff и code review

**Продакшн (решается после прототипа):** Unity, если приоритет — рекламные SDK и монетизация. Godot 4, если приоритет — скорость и отсутствие лицензий.

```
Зависимости: typescript, vite, vitest
Больше ничего. Новые пакеты — только с явного разрешения.
```

Рендер — Canvas 2D. Никакого WebGL, никаких шейдеров. Прототип рисует прямоугольники и круги.

## 3. Ключевые модули — точные требования

### 3.1 `Combat.ts`

```ts
damagePerHit(atk: number, def: number): number
  ratio = atk / max(def, 1)
  mult  = ratio^E / (1 + ratio^E)
  return atk * clamp(mult, floor, ceil)

totalDps(player: Stats, weapons: Weapon[], enemy: Stats): number
  для каждого типа:  atk = player.atk[type] * weapon[type].mult
  dps += damagePerHit(atk, enemy.def[type]) * attackSpeed
  return dps * critFactor(player)
```

Оружие **множит** стат атаки, не прибавляется к нему. Это не стилистический выбор: при аддитивной модели уровень оружия перестаёт влиять на урон к третьему острову, и вся система копий обесценивается. Проверено расчётом, подробности в `BALANCE.md` §7.1.

### 3.2 `EnemyBadge.ts` — самое важное в прототипе

Над каждым врагом три иконки типов, окрашенные по отношению `твоя_атака / его_защита`:

```
ratio >= icons.greenAt (1.5)  → зелёная
ratio <= icons.redAt   (0.7)  → красная
иначе                          → серая
```

Требования:
- пересчёт при каждом изменении экипировки или статов, без кеша на кадры
- цвет берётся из `balance.json.palette`, не хардкодится
- иконки видны **до** сближения, с расстояния как минимум в полтора экрана
- размер такой, что читается на 6 дюймах без прищуривания

**Игрок должен доверять иконкам абсолютно.** Любое расхождение между иконкой и реальным уроном ломает единственный механизм принятия решений в игре.

### 3.3 `Regen.ts`

```
Обычный реген (игрок и все враги кроме островного босса):
    если (сейчас - время_последнего_урона) > outOfCombatDelay:
        hp += maxHp * rate * dt

Островной босс — реген В БОЮ, всегда:
    hp += maxHp * bossCombatRegen * dt
```

«Урон» для сброса таймера — и полученный, и нанесённый.

Реген врага выше регена игрока намеренно: отступление от почти убитого противника должно быть болезненным.

### 3.4 `Weapon.ts`

```ts
get multiplier(): number
  return rarityMult[this.rarity] * (1 + levelStep * (this.level - 1))

static onAcquire(newWeapon, ownedOfSameType): Weapon
  if (balance.weapons.inheritLevelOnRarityUp)
    newWeapon.level = max(newWeapon.level, bestOwned(ownedOfSameType).level)
  return newWeapon

copiesForNextLevel(level: number): number
  return ceil(a * level^b + c)
```

Наследование уровня закрыто тестом. Если тест упал — не чинить тест, чинить код.

### 3.5 `DevPanel.ts`

Без этой панели баланс проверять невозможно. Обязательный минимум:

- множитель скорости времени: 1× / 10× / 100×
- мгновенный сброс всех таймеров респауна
- задать любой стат числом
- выдать N копий любого типа
- телепорт на любой остров
- переключение профиля баланса без перезагрузки
- показ реального DPS, входящего DPS и чистого DPS по текущей цели

Панель включается параметром `?dev=1` и полностью вырезается из продакшн-сборки.

## 4. Фазы

Каждая фаза заканчивается вопросом «работает ли это». Не переходить дальше, пока ответ не «да».

### Фаза 0 — ощущение (дни 1–3)

Белые прямоугольники на чёрном фоне. Никакого арта.

- палец водит игрока, враги стоят на местах
- сближение запускает автоматический размен, кнопки атаки нет
- три иконки над врагом
- реген обеих сторон
- смерть и респаун без штрафа
- hitstop, тряска камеры, вылетающие цифры, звук с рандомным питчем

**Критерий готовности: ты играешь в это 10 минут подряд и не хочешь закрыть.**

Не «терпимо». Не «ну ничего». Именно «не хочу закрыть». Если этого нет — останавливаемся и меняем боевую систему, а не идём дальше.

### Фаза 1 — прокачка (дни 4–8)

- три типа урона и три защиты
- три слота оружия, редкость, уровень, множитель
- мини-боссы, дроп копий, апгрейд оружия за копии
- наследование уровня при повышении редкости
- прирост статов с каждого убитого, с затуханием
- таймеры респауна, персистентность узлов между сессиями

**Критерий: понятно, зачем идти к конкретному мини-боссу.**

### Фаза 2 — гейт (дни 9–14)

- один остров целиком: обычные враги, элиты, 5 мини-боссов, босс
- босс с регеном в бою и слабостью к одному типу
- экран прогресса после смерти с процентом и дельтой
- запрет перехода на следующий остров до победы

**Критерий: первая попытка даёт 40–60%, и хочется попробовать ещё раз.**

Меряется на себе, честно, с секундомером. Если 20% — перетюнено. Если 85% — гейт не работает.

### Фаза 3 — мета (дни 15–20)

- три острова подряд
- корабль с трофеями за побеждённых боссов, пассивные бонусы
- сохранение в localStorage с версионированием
- офлайн-доход с потолком 4 часа

**Критерий: закрыл игру, вернулся через день, понятно что делать дальше.**

### Фаза 4 — стиль (дни 21–28)

- силуэтный арт по палитре из `balance.json`
- звук
- финальная настройка ощущения удара

**Критерий: скриншот выглядит как игра, в которую хочется зайти.**

### Фаза 5 — сборка

Решение про Unity или Godot. Порт логики, которая на этот момент уже проверена и не меняется.

## 5. Правила работы

**Все числа только из `balance.json`.** Ни одной магической константы в коде. Если понадобилось новое число — сначала в конфиг, потом в код.

**Детерминизм.** Весь ГПСЧ через `Rng.ts` с сидом. Один и тот же сид даёт одинаковый прогон — иначе баланс невозможно проверять.

**Фиксированный тик.** Логика считается шагами по 1/60 секунды с накопителем. Никаких расчётов от реального `deltaTime`, иначе на слабом телефоне баланс поедет.

**Тесты обязательны для:** `Combat.ts`, `Growth.ts`, `Weapon.ts`. Это три модуля, где ошибка не видна глазами, но убивает баланс.

**Задачи мелкие, коммит после каждой.** Один коммит — одна работающая вещь.

## 6. Симулятор баланса

Отдельная точка входа `src/sim/simulate.ts`, запускается из терминала без графики. Без него баланс придётся переделывать трижды вручную.

Что прогоняет: полный путь игрока по островам с усреднённой скоростью убийств, накопление статов, фарм копий, попытки боссов.

Что печатает по каждому острову:

```
ОСТРОВ 3 — Полифем (слабость: дробящий)
  Сила игрока после зачистки:   DPS 552    HP 6100
  Босс:                         HP 24000   DPS 128
  Реген босса:                  288 /с
  Чистый DPS:                   264 /с
  Время до смерти игрока:       47.6 с    [OK, порог 40]
  Прогресс за попытку:          52.4%     [OK, цель 40-60]
  Копий до победы:              ~170
  Время подготовки:             ~1.7 ч    [OK]
```

**Автопроверки, роняющие прогон с ошибкой:**

1. `T_death >= 40` секунд на каждом острове
2. прогресс первой попытки в диапазоне 40–60% на каждом острове
3. время подготовки растёт монотонно и нигде не превышает 12 часов
4. нигде нет `net_DPS <= 0` при снаряжении, соответствующем острову
5. фарм слабых врагов не выгоднее фарма сильных (проверка затухания)
6. уровень оружия с 1 до 30 даёт рост DPS не менее чем в 3 раза (защита от возврата к аддитивной модели)

Прогонять после каждого изменения `balance.json`.

## 7. Порядок настройки баланса

Строго по одному, иначе будешь ловить свой хвост:

1. `combat.typeExponent` — важность типов урона
2. `regen.*` — ощущение «дожать или отойти», самая чувствительная пара цифр
3. `islands.powerBase` — общий темп
4. `regen.bossCombatRegen` — жёсткость всех гейтов одной цифрой
5. `copies.*` — длина гринда, настраивается последней
