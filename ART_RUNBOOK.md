# NOSTOS — ART RUNBOOK

Пошаговый порядок работы с артом. Открывать перед любой задачей, где надо
сделать, поправить или заменить визуальный объект.

Зачем это отдельно от `ART_PIPELINE.md`: там **почему** так устроено, здесь
**что нажимать**. Если времени читать только один файл — читай этот, а в
`ART_PIPELINE.md` иди за обоснованием конкретного решения.

---

## 0. Что происходит в проекте, одним абзацем

Арт в NOSTOS больше не рисуется — он **собирается скриптом в Blender и
рендерится** в PNG под единственную камеру игры. Движок при этом прежний:
Canvas 2D, `drawImage`, никакого WebGL. Камера и солнце берутся из
`balance.json`, поэтому два объекта физически не могут разойтись по ракурсу или
направлению тени. Это и есть весь смысл затеи (`GDD.md` §3).

Старые нарисованные пропы (Draw Things) остаются в игре и работают. Остров
переводится на рендер **по одному объекту**, а не целиком.

---

## 1. Правила, которые нельзя нарушать

1. **Ни одного числа мира в скрипте ассета.** Размер, след, цвета — из
   `balance.json`. В скрипте живут только пропорции модели и параметры рендера
   (шероховатость, число граней), которых движок не видит.
2. **Оптику не трогать.** `props.cameraTiltDeg`, `props.lightX/Y/Z` — общие для
   движка и фабрики. Правка любого из них обесценивает ВСЕ отрендеренные
   ассеты: импортёр их отвергнет по несовпадению отпечатка.
3. **Всё детерминировано.** Никакого `random` — только `lib/variants.py` с
   явным сидом. Один сид — один и тот же файл.
4. **Источник истины — Python.** `.blend` это выход, а не вход. Руками в
   Blender ничего не моделируется.
5. **Приёмка только в живой игре.** Красивое превью ничего не доказывает.
6. **После правки `balance.json` — `npm run sim`.**

## 2. Алгоритм: новый ассет

### Шаг 1. Занести числа в `balance.json`

Прежде чем писать скрипт. В `props.sizes`:

```json
"prop-<имя>": { "fit": "height", "value": 190 }
```

`fit` говорит, по какой стороне ТЕЛА (без тени) задан размер. Значение — по
масштабной лестнице `GDD.md` §3, относительно `render.playerSize = 92`:

| Класс | Отношение | Единицы |
|---|---|---|
| Мелочь: черепки, галька, амфора | 0.20–0.35× | 18–32 |
| Утварь: давильня, телега, костёр | 0.60–0.90× | 55–83 |
| Растительность: куст, олива | 1.2–2.0× | 110–184 |
| Архитектурный элемент: колонна, стела, алтарь | 1.8–3.0× | 165–276 |
| Строение: хижина, ворота, портик | 2.5–4.0× | 230–368 |
| Ландмарк: храм, корабль, статуя | 4.0–7.0× | 368–644 |

Если объект широкий, проверь ширину отдельно: `boxW` у ворот 1.57, то есть при
height 190 картинка выходит 299 единиц — 83% ширины экрана (`virtualWidth 360`).
Больше — объект перестаёт помещаться в кадр.

Понадобился новый материал — добавь его в `props.materials` тремя тонами
(светлый, средний, тёмный) и поведение в `BEHAVIOUR` в `lib/materials.py`.
**Заметку внутрь `props.materials` класть нельзя** — см. §5.

### Шаг 2. Написать скрипт

`art/blender/assets/<имя>.py`. Обязательный интерфейс:

```python
from lib import damage, greek, materials, optics, shapes

ID = "prop-<имя>"          # тот же ключ, что в props.sizes
VERSION = 1
SIZE = optics.props()["sizes"][ID]   # из конфига, НЕ своей копией

def build(ctx):
    """ctx.body — коллекция тела, ctx.helpers — служебное, ctx.seed — сид.
    Возвращает список объектов тела."""
    ...
    return parts
```

Строй из готовых модулей, а не с нуля:

- `lib/greek.py` — `shaft`, `capital`, `column`, `broken_column`, `drum`,
  `lintel`, `cornice`, `stylobate`;
- `lib/shapes.py` — `revolve`, `block`, `bevel`, `move`, `turn`;
- `lib/damage.py` — `chip`, `lean`, `weather`, `rubble`;
- `lib/materials.py` — `library(["marble", "limestone", ...], seed)`;
- `lib/variants.py` — `unit`, `jitter`, `pick`, `chance`, `spread`.

Чего в модулях нет — сначала добавь ТУДА, потом используй. Ассет, который
лепит свою геометрию мимо библиотеки, не делает следующий ассет дешевле, а
именно в этом весь план (`ART_PIPELINE.md` §13).

**Пропорции строй с поправкой на проекцию.** При наклоне 55° высота сжимается
до `cos 55° = 0.574`, глубина — только до `sin 55° = 0.819`. Модель,
построенная «правильно», на экране превращается в широкую платформу с
пеньками. Строй заведомо выше и мельче в глубину — так же поступает
`src/ui/props/Models.ts`.

### Шаг 3. Быстрая итерация

```
node tools/blender.mjs <имя> --seed 1174 --px 1.5 --preview
```

`--px 1.5` — черновая плотность, прогон секунд десять. `--preview` складывает
тело и тень на игровую землю, ставит рядом столбик роста игрока и печатает
замер светлот. Смотри `art/out/prop-<имя>-preview.png`.

Крутись здесь, пока не сойдётся. Цель замера — **30 / 62 / 89**. Если тёмных
нет, кадр читается выцветшей плёнкой независимо от качества модели.

Проверяй три вещи:
- силуэт узнаётся, будучи залитым сплошным чёрным;
- фаска даёт светлую линию по верхним рёбрам;
- масштаб относительно красного столбика похож на правду.

### Шаг 4. Финальный рендер

```
node tools/blender.mjs <имя> --seed 1174 --px 4.6
```

`--px` это пикселей на единицу мира. Ориентир: на телефоне игра рисует
~2.4 px/единицу, на планшете ~4.6. Больше 4.6 смысла нет, потолок стороны
2048 px — при превышении плотность понижается автоматически. Ландмарк рендерится
минуты, не секунды: запускай фоном.

### Шаг 5. Импорт

```
node tools/import-blender-art.mjs prop-<имя>
```

Копирует тело и тень в `public/art/props/`, сверяет отпечаток оптики и печатает
готовые строки. Впиши их руками в:

- `src/ui/AssetManifest.ts` — две записи `SPRITES`: тело и `-shadow`;
- `src/ui/props/Pictures.ts` — добавь id в `PicturePropId` и `PICTURE_PROPS`
  (только для нового пропа; существующий там уже есть);
- `balance.json` → `props.rendered` — якорь и габарит;
- `balance.json` → `props.footprints` — след, если объект должен быть
  непроходим.

Руками, а не скриптом: оба файла — исходники с комментариями, автоправка их
испортит.

### Шаг 6. Проверка

```
npx tsc --noEmit
npm test
npm run sim            # обязательно, если трогал balance.json
npm run build
```

### Шаг 7. Приёмка в живой игре

```
npm run play -- boss --seed <новый>      # кадры в shots/
```

или руками: `npx vite`, открыть `http://localhost:5173/?dev=1&seed=<новый>`,
окно шириной ~520 px, в дев-панели `HP ×100` → `поднять босса` → `к боссу`.

**Сид всегда новый.** Сохранение узлов привязано к сиду, на старом босс окажется
уже убитым.

Смотри на объект **рядом с соседями**, а не отдельно:
- тень уходит влево-вниз и по форме похожа на сам объект;
- ракурс совпадает с амфорой и костром (они рисуются геометрией движка);
- подошва стоит на земле, объект не висит и не утоплен;
- если задан след — сквозь объект не проходят.

### Шаг 8. Коммит

Одна задача — один коммит, проект в рабочем состоянии.

## 3. Алгоритм: поправить существующий ассет

Меняешь только **размер или след** — правь `balance.json`, рендерить не надо:
`boxW`/`boxH`/`anchor` это доли, они от размера не зависят. След пересчитай
пропорционально или перерендери ради точного числа.

Меняешь **геометрию, материал или свет** — правь скрипт, дальше шаги 3–8.
`VERSION` в скрипте увеличь.

Тронул **оптику** (`cameraTiltDeg`, `lightX/Y/Z`, `shadowColor`, `shadowAlpha`,
любой тон в `props.materials`) — **перерендерить надо ВСЕ рендереные ассеты**.
Импортёр это поймает сам и откажется работать.

## 4. Приёмка: чем меряется результат

| Что | Чем проверяется | Норма |
|---|---|---|
| Диапазон светлот | `--preview` печатает замер | 30 / 62 / 89 |
| Силуэт | залить чёрным, узнаётся? | да |
| Масштаб | красный столбик в превью = рост игрока | по лестнице §2 |
| Ракурс | сравнение с амфорой/костром в игре | совпадает |
| Тень | направление влево-вниз, форма объекта | да |
| Вес | `ls -la public/art/props/` | ≤ ~600 КБ на ландмарк |
| Полигоны | печатает сборщик | проп ≤1500, строение ≤4000, ландмарк ≤10000 |
| Целостность | `npm test`, `npx tsc --noEmit` | зелено |
| Баланс | `npm run sim` | не хуже, чем было ДО правки |

Главный критерий — не число, а вопрос: **видно ли, что этот объект и соседний
нарисованы разными людьми?** Если нет — работа не сделана.

## 5. Грабли, на которые уже наступали

Все эти ошибки уже случились и стоили времени. Симптом → причина → лекарство.

**Рендер вышел пустой, ошибок нет.**
Перепутаны `sin` и `cos` в базисе камеры. Правильно: `up = (0, sin t, cos t)`,
`back = (0, −cos t, sin t)`, где `t = cameraTiltDeg`. Камера смотрит мимо сцены
и никак об этом не сообщает.

**Половина ассета за краем кадра.**
`matrix_world` в Blender считается лениво: сразу после `move()`/`turn()` объект
отдаёт старую матрицу. Нужен `bpy.context.view_layer.update()` — он уже стоит в
`shapes.world_points()`, но если читаешь матрицы где-то ещё, зови сам.

**Тень пришла сплошной плитой на весь кадр.**
`is_shadow_catcher` в Cycles отдаёт альфу вместе с собственным покрытием
плоскости. Мы этим не пользуемся: тень снимается белой матовой плоскостью и
маской по яркости (`render._mask_shadow`). Не возвращай shadow catcher.

**Скол съел половину колонны.**
Размер скола считался от самой длинной стороны блока, а у ствола это высота.
`damage.chip` берёт КОРОТКУЮ сторону. Если делаешь свой резак — так же.

**Тесты упали с `hexes.map is not a function`.**
В `props.materials` положили строку (заметку). `Optics.ts` перебирает эту
таблицу целиком и зовёт `.map` на каждом значении. Заметки — рядом с таблицей,
не внутри.

**Экспортёр посчитал след для одного размера, а движок рисует другой.**
`SIZE` в скрипте был своей копией числа. Читай из `balance.json`.

**Blender говорит, что движка `CYCLES` не существует.**
Интроспекция динамических enum врёт: `engine` и `view_transform` отдают
`['NONE']`. Присваивание при этом работает. Проверяй присваиванием.

**Цвета рендера не совпадают с палитрой.**
`view_transform` должен быть `Standard`. Filmic и AgX съедают насыщенность.

**Скриншот вышел с чужой страницы.**
Основной Chrome пользователя постоянно держит порт `9333`. Свой инстанс его
молча не займёт, а `/json/list` отдаст чужие вкладки. Брать случайный свободный
порт и искать вкладку по адресу.

**После прогона босс уже убит.**
Сохранение привязано к сиду. `localStorage.clear()` не помогает — уходящая
страница пишет состояние обратно на `pagehide`. Только новый `?seed=`.

## 7. Чего не делать

- Не переводить движок на WebGL или Three.js. Запрещено `CLAUDE.md`, и не нужно.
- Не ставить npm-пакетов. Blender — внешний инструмент, в `package.json` его нет.
- Не моделировать руками в Blender. Что нельзя описать скриптом — в проект не
  входит.
- Не брать готовые CC0-**модели**: чужая топология, чужой масштаб, чужой стиль.
  CC0-**текстуры поверхностей** можно, но почти никогда не нужны.
- Не заказывать новый арт старыми промптами Draw Things (`tools/preambles.mjs`,
  `ISLANDS.md` §1.4): они описывают отменённый плоский стиль. За диффузией
  остались только бесшовные текстуры поверхностей и концепт-наброски.
- Не подгонять якорь на глаз. Он считается из модели, и промахнуться им нельзя.
- Не «чинить» замер светлот подкруткой одного числа: свет считается
  (`ART_PIPELINE.md` §4.2), а не подбирается.
